# AI 中转服务实现计划

## 1. 目标

为四人团队提供统一的 AI 调用入口，集中管理 OpenAI、DeepSeek 及后续本地模型，避免在每台电脑上重复配置真实 API Key，并为 GMV 后台预留 AI 能力接入接口。

第一阶段部署在团队公共电脑上，通过局域网访问；后续如有远程办公或高可用需求，再迁移或扩展到阿里云。

## 2. 第一阶段架构

```text
团队电脑 A/B/C/D
        ↓ 局域网
公共电脑：AI Gateway
        ├── OpenAI API
        ├── DeepSeek API
        └── 可选：Ollama 本地模型
```

- AI Gateway：优先评估 LiteLLM；如需要更强的中文管理界面、渠道和用户配额，再评估 New API。
- 公共电脑使用固定局域网 IP 或 DHCP 地址保留。
- Gateway 只开放一个内部服务端口，例如 `4000`。
- OpenAI、DeepSeek 的真实密钥只保存在 Gateway 主机。
- 每位成员使用独立的内部 Token，并设置模型权限、额度和限流。

## 3. 实现阶段

### 阶段一：环境准备

- 确认公共电脑操作系统、CPU、内存、磁盘和网络情况。
- 关闭自动睡眠，配置开机自动启动。
- 为公共电脑设置固定 IP 或 DHCP 保留地址。
- 确认四台电脑处于可信的 Private 局域网。
- 确定 Docker Desktop、WSL 或原生运行方式。

### 阶段二：部署 AI Gateway

- 部署 LiteLLM 或 New API。
- 接入 OpenAI 和 DeepSeek API。
- 配置统一模型别名，例如：
  - `team-openai`
  - `team-deepseek`
  - `team-local`
- 设置内部访问 Token、超时、重试、限流和预算。
- 关闭或脱敏完整 Prompt/业务数据日志。
- 增加健康检查接口和基础运行日志。

### 阶段三：四台电脑接入

- 为每位成员创建独立 Token。
- 在客户端统一配置：
  - `AI_BASE_URL=http://ai-gateway.local:4000/v1`
  - 对应的内部 Token
- 测试普通文本、流式输出和模型切换。
- 验证某一成员超出额度后不会影响其他成员。
- 将公共技能、Prompt 和工作流放到私有 Git 仓库或受控共享目录中，避免与 API 密钥混放。

### 阶段四：接入 GMV 后台

- 在 GMV 后端新增 AI 客户端模块，不让浏览器直接访问 AI Gateway。
- 增加统一入口，例如：
  - `POST /api/ai/ask`
  - `POST /api/ai/selection-summary`
  - `POST /api/ai/product-draft`
- 由 GMV 后端先计算准确业务数据，再把脱敏后的数据发送给 AI。
- AI 只负责摘要、分类、解释和生成草稿。
- 结果写入前使用 Zod 等 schema 校验。
- 商品发布、价格修改和买家回复必须保留人工确认。

## 4. 首批 AI 功能

1. GMV 经营助手：解释 GMV、订单数、取消金额和店铺异常。
2. 选品分析助手：总结类目、关键词、竞争和候选商品风险。
3. 商品文案助手：生成俄语标题、卖点和属性草稿。
4. 买家问题助手：分类问题并生成回复草稿。
5. 每日经营日报：汇总各模块数据并生成简报。

数值、金额、转化率和排名必须由程序计算，不能交给模型自行推算。

## 5. 安全与运维要求

- 不把 OpenAI、DeepSeek 真实 API Key 放入前端、技能文件或 Git 仓库。
- Windows 防火墙只允许团队局域网访问 Gateway 端口，最好进一步限制为四台电脑的 IP。
- 不做路由器端口映射，不直接暴露到公网。
- 不让 AI Gateway 直接读取 GMV 的 SQLite 文件或共享数据库目录。
- 只传必要字段，过滤店铺密钥、客户信息和内部凭证。
- 商品标题、CSV 内容和买家问题都按不可信输入处理。
- 记录调用人、模型、耗时、Token 用量和错误，但默认不记录完整业务 Prompt。
- 为公共电脑配置定期备份、自动更新和服务异常告警。

## 6. 验收标准

- 四台电脑均可稳定调用 OpenAI 和 DeepSeek。
- 切换模型时不需要修改业务代码，只需切换模型别名。
- 任意一个上游 API 故障时，系统能返回明确错误或切换备用模型。
- 每位成员可单独统计和限制用量。
- 公共电脑重启后 Gateway 能自动恢复。
- 局域网外无法直接访问 Gateway。
- GMV 后台无法因 AI 调用直接修改商品、价格或订单数据。
- 断开 AI Gateway 后，GMV 原有订单同步和看板功能仍然可用。

## 7. 云端扩展条件

满足以下任一条件后，再评估部署到阿里云 ECS：

- 团队成员经常在不同网络环境办公。
- 公共电脑无法保证全天运行。
- 需要手机或外地访问。
- 需要更完善的监控、备份和高可用。
- 需要同时服务多套 GMV 实例。

云端版本应使用 HTTPS、VPN 或访问控制，不应直接公开 LiteLLM/New API 管理端口。

## 8. 建议的首个里程碑

先完成“公共电脑部署 LiteLLM + 接入 OpenAI/DeepSeek + 四台电脑各自 Token + 健康检查和用量统计”，暂不接入 GMV 业务功能。稳定运行后，再实现 GMV 经营助手作为第一个业务场景。
