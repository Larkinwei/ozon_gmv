# Ozon GMV Command Center — Design System

页面级规则位于 `pages/`，存在时优先于本文件。

## 设计方向

- 深色运营指挥中心：高对比、数据优先、低装饰。
- 不使用科幻 HUD、大面积渐变、持续发光、玻璃拟态或 Emoji 功能图标。
- 图标统一使用 Lucide SVG；正文使用系统字体栈，兼顾中文与俄文。

## 尺寸与排版

- 采用 4/8px 间距体系、12px 卡片圆角、1px 边框和轻量阴影。
- 金额、数量和时间统一使用 `font-variant-numeric: tabular-nums`。
- 大屏 KPI 44–56px，大屏正文不低于 16px；管理页正文不低于 14px。
- 所有交互区域至少 44×44px；输入框标签始终可见。

## 交互与状态

- hover/focus/状态过渡控制在 150–300ms，不能造成布局位移。
- 键盘焦点必须可见，颜色不是唯一状态表达。
- 加载使用固定尺寸骨架；错误必须包含原因和恢复动作。
- 新订单只播放一次 220ms 位移与淡入；减少动态效果时移除位移。
- 断线、限流、权限不足、空数据和同步延迟分别显示明确文字。

## 响应式

- 检查 375、768、1024、1440、1920 五个宽度。
- 1024 以下 KPI 改为 2×2，实时订单流移到图表下方；768 以下改单列。
- 1920×1080 Wallboard 不允许页面纵向滚动，只有订单流内部可滚动。

## MY 数据 Tab

- 继续使用选品分析工作区的 Tab、卡片和工具栏样式，不引入独立主题。
- 导入、筛选和清空是同一层级的操作；清空使用危险色并要求二次确认。
- 指标卡只展示当前采集日，明确提示月销量和月销售额为滚动指标，不跨天相加。
- 数据表在桌面端保持高密度；768px 以下切换为商品卡片，主图固定 42px 并懒加载。
- 文件夹导入必须先显示文件数、有效行、重复行和错误行，再允许提交。
- 空数据、无匹配结果、导入中和部分错误都要提供下一步操作文字。

## 交付检查

- [ ] 无 Emoji 功能图标，图标均有一致来源。
- [ ] 正文符合 WCAG AA，图表数据线与背景至少 3:1。
- [ ] 所有表单都有可见标签、就地错误和恢复说明。
- [ ] 键盘可完成所有操作，图标按钮有无障碍名称。
- [ ] `prefers-reduced-motion` 生效。
- [ ] 手机端无横向溢出，固定区域不遮挡内容。
